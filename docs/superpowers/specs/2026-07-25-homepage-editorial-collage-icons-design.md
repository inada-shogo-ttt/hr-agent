# トップページ 編集コラージュアイコン差し替え設計

## 目的

公開トップページにある汎用的な線画アイコン11点を、紙・写真・文具を使った編集コラージュへ差し替える。既存の情報構造とブランドカラーを保ちながら、生成AIサービスにありがちな魔法・きらめき・均質な線画の印象を弱め、求人原稿を人が編集・改善するプロダクトらしい手触りを加える。

## 対象

`app/page.tsx` 内の次の3セクションを対象とする。

1. 「求人原稿の作成と改善を、ひとつの場所で」の4パネル
2. 「求人作成から改善まで 3つのステップ」の3パネル
3. 「原稿の品質と改善を支える機能」の4パネル

合計11点のアイコンを個別の画像素材へ差し替える。

## 対象外

- カードのコピー、順序、情報構造の変更
- セクションの配色やレイアウトの全面変更
- ヒーロー、ナビゲーション、対応媒体、活用例など他セクションのアイコン変更
- アニメーションや新しい操作の追加

## アートディレクション

### 共通表現

- 上から撮影した小さな編集デスクを思わせる、切り抜き写真と紙片のコラージュ
- 紙、写真プリント、付箋、赤鉛筆、クリップ、校正記号、簡潔な図表を使用
- オフホワイト、チャコール、ブランドのコーラルピンクを中心に限定した配色
- 画像内に文字、数字、ロゴ、透かしを入れない
- 過度な光沢、ネオン、SF表現、魔法の杖、きらめき、ロボットなどの生成AI的な記号を使わない
- 小さく表示しても主題が判別できる、中央寄せの単純なシルエット
- 11点を同一の撮影角度、紙質、影、彩度で統一する

### 背景と可読性

最終素材は背景透過PNGとする。白いカードでは薄い紙の影が見え、チャコール背景のFEATURESカードではオフホワイトの紙片が輪郭として機能するようにする。被写体の外側に十分な余白を取り、カード内でクロップされない構図にする。

## 各画像のモチーフ

| セクション | パネル | モチーフ |
|---|---|---|
| 課題 | 同じ求人情報を何度も入力している | 重なった求人票と複写紙 |
| 課題 | 媒体ごとの書き分けが難しい | 中央から4方向へ分岐する原稿用紙 |
| 課題 | 求人に合う画像も用意したい | 写真プリント、トリミング枠、色見本 |
| 課題 | 掲載後の改善方法が分からない | 赤鉛筆で修正された紙のグラフ |
| 3ステップ | 求人情報を登録 | クリップ留めされた入力シートとチェック印 |
| 3ステップ | 媒体別原稿を作成 | 原稿用紙、校正記号、赤鉛筆 |
| 3ステップ | 掲載結果から改善 | レポート用紙、付箋、上向きグラフ |
| 機能 | 求人トレンドを調査 | 新聞風の切り抜き、虫眼鏡、調査メモ |
| 機能 | 4媒体向けに原稿作成 | 4枚に分けた異なる紙面 |
| 機能 | サムネイルも同時生成 | 写真プリント、カッター、色見本 |
| 機能 | 掲載結果から改善 | 数値レポート、赤字校正、改善矢印 |

似た意味を持つ画像でも、工程と機能の違いが分かるように道具と構図を変える。特に2つの「掲載結果から改善」は、3ステップ側を付箋中心、FEATURES側を赤字校正中心にする。

## 素材構成

- 保存先: `public/images/landing/icons/`
- 形式: 背景透過PNG
- ファイル: 用途を示す英語のケバブケース名を使用
- 生成元: built-in image generation
- 生成方法: 11点を用途ごとの個別プロンプトで生成し、共通のスタイル指定をすべてに含める
- 背景除去: 単色クロマキーで生成後、ローカルの背景除去処理で透過PNGへ変換

各画像はプロジェクト内へ保存し、生成ツールの既定保存場所を実行時参照先にしない。

## 実装

`app/page.tsx` の各配列で、Lucideコンポーネントの代わりに画像パスを保持する。表示には既存のNext.js `Image` を使用する。

- 課題パネル: 現在の32px線画に代えて、約48〜56px角で表示
- 3ステップ: 現在の48px線画に代えて、約64〜72px角で表示
- FEATURES: 現在の40px線画に代えて、約56〜64px角で表示

素材は説明見出しと重複する装飾要素なので、`alt=""` としてスクリーンリーダーの重複読み上げを避ける。画像の寸法を明示してレイアウトシフトを防ぐ。カードの高さ、番号バッジ、矢印、本文、既存アニメーションは維持する。

## 失敗時の扱い

- 生成画像に文字、ロゴ、不自然な指や道具、過剰なAI記号が入った場合は採用しない
- 背景除去でコーラル色や紙の縁が欠ける場合は、閾値を調整して一度再処理する
- 小サイズで意味が読めない場合は、要素を追加せず主題を1〜2要素へ減らして再生成する
- 白背景またはチャコール背景のどちらかで輪郭が沈む場合は、紙の明度と影のみを調整する

## 検証

1. 11ファイルがすべてプロジェクト内にあり、参照切れがない
2. 全画像にアルファチャンネルがあり、四隅が透明
3. 白背景とチャコール背景の両方で輪郭が判別できる
4. デスクトップとモバイルでクロップ、重なり、カード高の不揃いがない
5. 画像内に文字、ロゴ、透かし、魔法・きらめき表現がない
6. `npm run build` が成功する

## 成功条件

- 対象11点から既存のLucide線画アイコンがなくなる
- 各画像がパネルの意味を小サイズでも伝える
- 11点に統一感がありつつ、同じ画像の使い回しに見えない
- 既存のブランドカラー、コピー、カード構造、レスポンシブ表示を損なわない
- トップページ全体が、生成AIの抽象表現よりも求人原稿の編集・制作という具体的な仕事を感じさせる
