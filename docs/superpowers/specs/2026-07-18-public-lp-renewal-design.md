# 公開LPリニューアル設計

## 目的

新規顧客が、採用エージェントで「何ができるか」「自社の求人作成をどこまで任せられるか」を短時間で理解し、求人原稿の作成へ進める公開LPにする。

現在のルート `/` は未認証時に `/login` へリダイレクトされるため、既存のLP本体が公開されない。LPを未認証でも表示可能にし、ログイン後の業務画面と役割を分離する。

## 対象と非対象

### 対象

- 新規顧客向けの公開LP（`/`）
- 未認証ユーザーが `/` を閲覧できる認証設定
- LPの情報設計、コピー、ビジュアル、レスポンシブ表示
- CTAの認証状態に応じた遷移

### 非対象

- 料金ページ、問い合わせフォーム、CMS、分析基盤の追加
- 実在しない導入実績・成果数値の掲載
- 求人作成・ログイン・認証フロー自体の仕様変更

## 設計方針

採用エージェントを「AIエージェントの集合」ではなく、求人作成から媒体別最適化、掲載後の改善までを一貫して支援する採用オペレーション基盤として訴求する。

ビジュアルは既存ブランドのコーラル（`#ff385c`）をアクセントに用いる。白と濃いチャコールを基調に、求人成果物を思わせる紙面・編集のモチーフを取り入れる。装飾的なカードを増やさず、出力物とプロセスを主役にする。

## ページ構成

1. **ヘッダー**
   - ロゴ、アンカーリンク（できること・対応媒体・仕組み）、ログイン。
   - 主CTAは「求人原稿を作成する」。

2. **ヒーロー**
   - 見出しは「伝わる求人は、つくれる。」を基調とする。
   - 説明は、最小限の入力で原稿作成・媒体別最適化・掲載後改善まで進められることを伝える。
   - 右側に原稿と対応媒体の出力状態を示すプロダクトプレビューを置く。
   - CTAは「求人原稿を作成する」と「出力サンプルを見る」。

3. **価値の要約**
   - 「必要な情報を入力」「媒体ごとに整える」「掲載後も改善」の3項目。
   - 未検証の時間・成果数値は使わない。

4. **成果物プレビュー**
   - 原稿、サムネイル、4媒体への出力、改善差分を視覚的に説明する。
   - 実データがないため、サンプルであることが分かる表記をする。

5. **3ステップの利用フロー**
   - 求人を登録する、原稿を受け取る、掲載後に改善する。

6. **品質の根拠**
   - トレンド調査、事実確認、改善履歴の活用を紹介する。
   - AIエージェント数は補足情報に留め、中心訴求にしない。

7. **対応媒体**
   - Indeed、AirWork、JobMedley、HelloWorkを明記する。

8. **最終CTAとフッター**
   - 「最初の求人原稿をつくる」で行動を促す。
   - 対応媒体とログインへの導線を再掲する。

## コンポーネントと責務

- `app/page.tsx`: LPのセクション構成と静的コピーを担当するサーバーコンポーネント。
- `app/components/home/*`: ヒーローのプレビュー、必要な軽量な視覚コンポーネントを担当する。
- `AppHeader`: 公開LP用のナビゲーションを認証済みアプリ用ヘッダーと混同しない。必要ならLP専用ヘッダーに分離する。
- `middleware` / Supabase middleware: `/` を公開パスに加え、認証を要求する業務ルートの保護を維持する。

## CTAと認証の扱い

- 未認証のCTAは `/login?next=/jobs` へ遷移する。
- 認証済みのCTAは `/jobs` へ遷移する。
- ログイン後は `next` パラメータがあれば安全な内部パスのみ遷移先として利用し、なければ既存どおり `/jobs` に遷移する。
- `/`、`/login`、静的アセット、認証APIは公開パスとする。

## レスポンシブ・アクセシビリティ

- モバイルはヒーローを縦積みにし、プレビューの可読性を優先する。
- 見出し、本文、CTAの階層を明確にし、本文は十分な文字サイズと行間を確保する。
- アンカーリンク、ボタン、デモ内の状態はキーボード操作とスクリーンリーダーで意味が分かるようにする。
- `prefers-reduced-motion` 時は非必須アニメーションを停止する。

## 検証

- 未認証で `/` が200で表示され、`/jobs` がログインへ保護されることを確認する。
- 認証・未認証それぞれでCTAの遷移を確認する。
- デスクトップとモバイル幅でレイアウト崩れがないことを確認する。
- `npm run build` を実行し、型・ビルドエラーがないことを確認する。

## 成功条件

- 公開LPが未認証で閲覧できる。
- ファーストビューだけで、求人原稿の作成・媒体別最適化・改善の範囲が理解できる。
- AIの内部構成ではなく、顧客が受け取る成果物と業務の変化が主訴求になっている。
- 実績がない段階でも、根拠のない数値や顧客の声を掲載しない。
